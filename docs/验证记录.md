# 验证记录

日期：2026-10-15。对象：课序 0.1.0 源码，Expo SDK 57。以下检查在 Windows 上完成，不等同于真实学生账号或 iOS 真机验收。

## 已通过

- 使用 Node.js 24 运行测试：21 项通过。除课表解析、变更比较、冲突和学校网址校验外，还模拟了网页验证码会话、登录提交、成功跳转、课程 JSON 读取与同步、不同失败原因、跨站请求拒绝及解绑。
- `npm run typecheck`、`npm run lint`：通过；`npx expo-doctor`：21/21 项通过。
- iOS JavaScript 资源与网页资源可以导出；导出结果不是 IPA。
- 440 × 956 网页视口中的今日课程、周课表、详情、变更和设置页已检查。网页绑定页包含学校验证码、学号和密码输入框及可点击的绑定按钮。
- 本站 `/school?action=captcha` 从学校获取到真实 JPEG 验证码并维持验证码 Cookie；空表单返回 400，未绑定同步返回 401，解绑返回 204。
- 学校公开登录页只读检查确认表单路径和字段；真实账号和验证码未由自动化提交。
- 学生反馈官网账号可登录但课序曾显示笼统的“登录未完成”。核对学校当前 `md5.js` 后发现官网计算密码摘要前追加固定后缀，本站原先遗漏；现已按官网脚本修正，并跟随登录后的首页跳转，分别报告登录拒绝与课表页面无法解析。
- 学生再次绑定后反馈学校课表页不可读取。对已登录的学校页面只检查结构，确认 14 列课程清单共 39 行、时间字段与合并单元格符合解析规则。公开脚本表明课程清单由 `/student/courseSelect/thisSemesterCurriculum/ajaxStudentSchedule/callback` 的 JSON 动态生成，节次由 `/ajax/student/getSectionAndTime` 提供。网页服务端现分别读取这两个接口，并用现有模型验证后才替换课表。学生随后在网页用真实账号重试，反馈“绑定成功”；自动化未读取或保存真实课程内容。
- HTTPS 网页会话已加上 AES-GCM 加密、Secure/HttpOnly Cookie 和篡改拒绝；21 项模拟测试、类型检查、Lint 及包含 `/school` API 路由的网页导出通过。EAS Hosting 已确认支持 Expo Router 服务端路由、免费计划的 `expo.app` 地址，以及 `sensitive` 服务端环境变量。Expo 账号、项目及生产环境密钥已配置，并完成网页预览部署。
- 学生反馈 Cloudflare 临时隧道在 iPhone 蜂窝数据下能打开课表并同步，证明现有网页与学校适配器在本机服务场景可用；隧道依赖本机持续运行。

## 已知边界

- 网页只在打开时和前台每 5 分钟检查学校课表；关闭网页后不能保证立即发现课程变化。
- 本站局域网地址和学校入口都是 HTTP。网页绑定时学号、密码会先到本站服务器，随后服务器向学校登录；局域网 HTTP 传输不加密，只能在可信网络测试。公网 HTTPS 可加密用户至本站的传输和本站会话 Cookie，但本站至学校仍走 HTTP，无法保证端到端保密。
- 学校登录页或课表结构变化会导致读取失败；此时保留最近的本地课表，不应把它当成最新结果。
- `npm audit` 此前报告 Expo/React Native 依赖链的 28 项告警，尚未用可能破坏 SDK 57 兼容性的强制升级处理。
- 演示课表完全虚构。源码和交付包不包含真实学生账号、密码或课表。
